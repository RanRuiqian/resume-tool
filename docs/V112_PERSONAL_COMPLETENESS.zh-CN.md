# v1.12 固定简介、职业背景完整性与专业表达

状态：开发分支 `feat/ai-led-resume-planning`，Draft PR #13；未合并、未部署。日期：2026-11-01。

## 根因与新旧逻辑

旧流程把简介作为岗位定制写作对象，再用 `focusSummary` 按 JD 删除分句，90 字/50 词长度限制也可能压掉教育身份和工作背景。选材把单页 8 条、每段 3 条、技能数量等当成硬上限，提示词强调直接相关，缺少工作和组织背景的完整性要求。输入已经包含 `work.kind`，但未充分使用。导出又可逐级缩小字号，掩盖内容分配问题。

新流程先理解完整画像，再分层考虑直接相关、可迁移工程、职业/组织背景及低价值内容。正式工作、实习和未细分性质的有效工作都参与背景考虑；不会把未细分记录自动改成全职。明确的兼职、社团、志愿按原性质处理。主选与候补都由 AI 决定，程序不根据关键词擅自替换选材。

固定条数不再决定方案是否合法。传给模型的是目标页数、当前字体、行距、页边距、模块、固定简介占用长度和软参考。来源 ID、所属经历、重复、启用状态、估算 GPA 等事实边界仍是硬校验。有有效工作/组织却没有主选、候补或具体省略说明，会使用既有的一轮局部修复恢复考虑；不是静默丢弃。

## 固定简介

- 直接使用 `profile.summary` 两种语言的已确认/人工内容；无状态旧字段按兼容的人工内容处理。机翻及过期内容不自动充当已确认简介。
- 简介不发送给选材或写作模型，不纳入副语言逐条翻译，也不再调用 `focusSummary`、`guardSummary` 等旧岗位简介函数。新简历把两段原文保存为 `sourceId='summary'` 的快照。
- 同一资料生成不同岗位时简介完全一致。资料页后续修改只影响未来生成，不遍历或覆盖旧简历。旧简历某语言为空时也不从最新资料偷偷补入。
- 「我的资料 → 固定个人简介」可手动修改。缺失另一语言时可主动获取一次翻译建议；建议只暂存在组件中，数字/事实对照未通过时不能确认。用户确认且原文/目标文字未变才保存。批量翻译跳过简介。
- 本轮补全对照词表中的 `大学/学院 ↔ University/College` 和 `目前 ↔ Currently`，避免正确的固定简介翻译被误报；单侧学校、完成/进行中、数字或参与程度变化仍会提示或阻断。
- 用户在任务中认可的真实简介不写入代码、示例或通用默认值。环境不能访问其浏览器资料，需由用户在自己的资料页粘贴、编辑并确认。

## 工作、组织和版面

`inferWorkKind` 只产生本次展示/选材提示，母库不改写。专业工作按真实职业背景优先保留，岗位决定详略；组织通常保留一段 1–2 条真实事实。无关兼职可不选。新生成简历按性质单列校园经历，不混入职业工作；旧简历/模板保持历史布局。

AI 可以提供少量候补，与主选一起写作和本地化。程序结合双语版面估算补入有价值候补；优先补缺失的工作/组织。浏览器再用实际 PDF 页数核对，候补导致超页时撤回候补；主要工作与项目仍超页则提示两页或手动精简。没有新增完整 Pro 轮次。

版面估算不能证明每次实际剩余空间恰好可容纳某项素材，无法测量 PDF 时会明确提示。类别缺失会说明没有启用素材、AI 的省略理由，或候补因空间未展示；内容稀疏会提示手工补选。没有真实候补时不会编造、重复或加空话填充。

新简历记录 `layoutPolicy='readable'`，自动适配可以调整间距，但保持用户设置的正文大小和行距。超出目标页数正常提示，不无限缩字。既有 1/2 页、模板和手动勾选/取消仍有效。

## 专业表达与安全

AI 可以根据不同岗位重新组织语句、专业概括同一经历内的真实动作和结果。单要点保留 `sourceId`；跨要点概括另外记录 `sourceIds`，必须包括主 ID，全部已选、真实、同属一段经历且各只使用一次。跨公司/跨项目、未选、未知、重复或缺少主来源均拒绝。

改写对完整来源池执行原有 `guardRewrite`、数字/币种/百分比、参与程度、课程/仿真/计划/预计状态及实体检查。危险改写仍最多局部修复一次，失败用其真实来源的保守文本；选材修复失败仍中止，不规则降级。不会因为措辞专业而放过“参与→主导”“仿真→部署”或新软件、新成果。

事实审查显示全部合并来源，可恢复全部原文。取消其中一个来源会拆回其余原文；合并不会让用户失去逐条选择权。JSON 和备份恢复保留可选追溯字段，无数据库版本升级。英文项目标题只在新简历中去相邻完全重复词，已在标题中的课程性质不在副标题重复堆叠，不改机构或证书名称。

## 文件分工

- `src/ai/fixedSummary.ts`、`FixedSummaryEditor.tsx`：固定快照及建议确认；`ProfilePage.tsx`、`translate.ts`、`selection.ts`：编辑、批量翻译与手动控制。
- `aiPlanner.ts`、`prompts.ts`：完整画像、主选/候补、软预算与缺失理由；`contentStrategy.ts`：版面估算、实际 PDF 核对、完整性说明。
- `generate.ts`、`provenance.ts`：写作、同经历概括及双语来源；`sourceIndex.ts`、`factAudit.ts`、`MaterialPool.tsx`、`ItemsEditor.tsx`：合并来源审查与控制。
- `render/layout.ts`、`render/resumeText.ts`、`export/fit.ts`、`export/zip.ts`：顺序、校园模块、英文去重及可读性；`types/index.ts`：仅追加可选字段。

## 自动化与人工边界

新增 A–F 回归覆盖固定简介跨 JD 一致、旧记录不变、职业/组织、候补空间、专业表达及危险改写阻断、多来源审查恢复/取消、JSON/IndexedDB 备份恢复、Demo、小/中/丰富资料双语 PDF 与 DOCX。

合成资料导出中，小/中资料分别一页，丰富资料两页，字号/行距不缩小。PDF 检查预期文本存在、无替换字符、页外文本和意外空白页，并渲染抽查。DOCX 检查结构、文本、模块与字体设置。环境未安装 Word/LibreOffice，不能自动证明 Word 的最终分页和视觉表现；这项必须人工打开确认。真实 Pro 语义质量、真实资料/JD 的最终选材仍必须人工验收，不能用 mock 测试冒充真实验收。

原浏览器 API 配置测试把 JD 的 token 预算误算作连接测试。本轮按请求的实际用途区分，并分别断言连接请求仍为 8、JD 请求仍为 12000，没有删除检查。

## Codespaces 最简验收

```bash
git fetch origin
git switch feat/ai-led-resume-planning
git pull --ff-only
npm ci
npm run dev -- --host 0.0.0.0
```

打开转发的预览地址，不清空 IndexedDB；若浏览器地址不同而没有原资料，手动使用自己已有的备份导入。

1. 在「我的资料」粘贴/确认本轮认可的中文简介；检查英文，有需要再主动获取建议并确认。确认旧简历仍保留原文。
2. 检查工作、学生组织的性质和启用状态，分别用机械设计、机器视觉 JD 生成。两份简介应完全相同；正式工作/工程实践应被合理保留；组织有空间时显示，缺失有原因。
3. 用事实审查查看专业改写及全部来源，试着取消组织经历或一个合并来源，再补选，确认不改母库。
4. 分别用 1/2 页设置导出两种语言的 PDF/Word；核对文字、换行、日期、课程/仿真性质、页数及留白。Word 用本地办公软件打开检查。主要内容过多时采用两页，避免用小字硬塞。

完成后保持 Draft，等待人工验收；不合并、不部署，不使用真实用户 Key 做自动化。
