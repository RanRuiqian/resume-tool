## 1. 产品一句话与负责人的最新决定

纯前端 AI 简历工具：导入个人资料母库 → 上传岗位 JD 截图 → AI 选材并撰写针对该岗位的中英文简历 → 左侧勾选 / 编辑、右侧预览 → 导出中英 PDF + Word。

本轮负责人明确的决定（优先级高于旧文档）：

1. **事实检查放宽**：只拦「原文没有的数字」「原文没有的工具 / 专有名词」「凭空抬高（参与→主导、仿真→部署、新增工厂 / 商业 / 全职 / 独立等说法、把未完成写成完成）」。**省略**课程 / 仿真 / 协助等限定词不再整条退回原文。
2. **个人简介按岗位定制**，姓名下面的求职方向（headline）也按岗位定制。目标是「让人觉得我适合这个具体岗位」，每个岗位一份专属简历。
3. **英文版直接按英文简历习惯写**，不再从中文机翻。
4. 附加功能优先级：**投递管理、联合岗位（同一公司最多 3–4 个岗位共用一份简历）、课程库（按岗位挑本科 / 硕士课程）、求职信** 都重要，保留并继续完善；**面试自我介绍**以后再说（目前只在投简历阶段）。
5. 风格：工科、专业务实、白纸黑字，不要花哨。负责人暂时没有风格样板简历。
6. 预览新版本时负责人**不做备份**，而是重新导入资料库，从流程第一步走起。
7. 给负责人的操作说明要短：一次一个命令或一个界面动作。给 AI 的文档则要详细。
10. **（第三轮）核心功能 = 资料库导入 → 单岗位生成 + 联合岗位生成（同公司 3–4 岗一份简历）→ 编辑导出 → 投递记录。** 联合岗位与投递记录都是核心，任何发布前都要回归这两块。
11. **（第三轮）尽快可用**：负责人急着投简历。计划是本轮通过后，经负责人**明确同意**再把 PR 链合并进 main、发布到 GitHub Pages 正式网址作为「稳定可用版」；之后新功能继续在分支 + Codespaces 预览开发，负责人说「可以上线」才发布。**未经负责人明确同意不得合并 / 部署。**
8. **（第二轮）简历要基本填满一页**：负责人认为第一版筛得太严。相关的写细，其它真实经历简短带上（更多课程、核心项目更多要点、本科学生会经历、与岗位不直接相关的技能也可以放），因为不知道 HR 看重哪一点。手动勾选只用于微调，默认结果就该完整。
9. **分类**：学生会、校办教师助手 → 校园经历；肯德基 / 沃尔玛等兼职 → 标为「兼职」，**不得写成实习**，空间够才放。

## 2. 本轮改了什么（为什么改）

问题来源：负责人用真实 V7 母库 + ABB 上海「机械设计工程师」JD 生成后导出，发现简历「太 AI」「不够针对岗位」，英文版大量中文，姓名 / 公司带句号等。

### 2.1 V7 导入清理 — `src/ai/factLibrary.ts`
| 现象（ABB 导出） | 根因 | 修复 |
|---|---|---|
| 姓名、单位、职位后面带「。」 | 标量字段直接搬原文整句 | 新增 `clean()`：姓名、单位、职位、学校、学位、专业、项目名、技能名、证书 / 奖项名、求职方向、成绩原文去掉句末标点 |
| 英文版课程显示 `专必; 专必; 实践` | 本科课程行是「名称｜性质｜学分｜成绩｜概述」，第二列（性质）被当成了英文名 | 第二列是课程性质词或含中文时不作为英文名 |
| `English personal summary: …` | INTRO 行的字段名没去掉 | 去掉「中文个人简介：」「English personal summary:」等字段名 |
| 项目副标题显示 `06 核心项目 1：数字耳镜` | 「性质」写在「年份：2026；性质：…」同一行，取不到时用栏目标题顶替 | 从任一分句读取「性质：」；不再用栏目标题；性质分句里的起止日期作为项目日期；`性质` 行不再作为要点 |
| 技能分组叫「基础使用」「本科毕业设计」 | 【】标签是熟练度 / 证据性质，被当成分组 | 分组 = 小标题（去掉「课程实验」「与真实实践」等后缀，如「工程/原型」「机器人/视觉计算」）；【】标签存入 `SkillEntry.level` 并发给 AI 选材 |
| 英文技能里出现 `MATLAB、Computer Vision Toolbox` | 纯英文工具列表用中文顿号 | 无中文字符的工具名把「、」换成 `, ` |
| `学校（英文）` 只识别「English（中文）」 | — | `bilingual()` 也识别「中文（English）」，如「轮机工程（Marine Engineering）」 |

真实 V7 本地核验（私有原件不入 Git）：`npm run verify:import -- <本地路径>` → 299/299 编号事实、本科 76、硕士 6、核心项目 2，`issues: []`；实体数与之前一致（教育 2、工作 8、项目 21、课程 82、技能 46）。

### 2.2 AI 撰写重做 — `src/ai/prompts.ts`（`AI_WRITE_PROMPT`）、`src/ai/generate.ts`（`generatePrimaryAi`）
- **提示词**：旧版几乎全是禁令、没有正面示范，模型只能写安全的套话。新版先讲读者（10 秒扫读的招聘工程师）和目标，给出写法要点、一个**虚构**的好 / 差示例，事实边界只保留最关键几条。
- **一次撰写同时给中英文**（`items[].zh / en`），各按本语言习惯写；英文不再由中文翻译。只有缺失或未通过检查的条目才走 `localizeAi` 补齐（`generateResumeInner` 里按 `missing` 列表调用）。
- **按岗位定制简介与求职方向**：撰写返回 `summary {zh,en}` 与 `headline {zh,en}`；`headline` 存入新的可选字段 `ResumeDoc.headline`，`render/layout.ts` 优先显示它。若出现资料外的数字 / 工具 / 机构 / 专业则回退到母库固定简介、资料库求职方向，并写入 notes。固定简介作为参考发送（`candidate.fixedSummary`）。
- **放宽的事实护栏** `factGuard()`（`src/quality/resumeGuard.ts`）：只拦新数字 / 百分比 / 币种、`INFLATE` 类说法（已获得 / 授予、全职、商业、独立、公司、医院、工厂 / 现场）、参与程度抬高，以及原文是计划 / 未完成时写成「完成 / 实现」。旧 `guardRewrite()` 保留给其它调用方，撰写路径不再使用。工具 / 专有名词检查对比「两种语言的原文 + 资料库全文」。
- 发给撰写模型的 JD 现在包含职责、必备、加分与关键词（以前只有岗位名称 + 已判定的要求）。

### 2.3 英文简历中的中文短字段 — 新文件 `src/ai/labels.ts`
- `resumeLabelTargets()`：只收集**当前简历选中**条目里缺另一语言的短字段（学校 / 学位 / 专业 / 单位 / 职位 / 项目名 / 角色 / 技能名与分组 / 证书奖项名与机构 / 课程名）。中文方向只翻译超过 6 个词的英文（工具名、官方英文名保持英文）。
- `fillResumeLabels()`：一次批量翻译，写回母库（状态 `machine`，以后复用）并更新本简历课程快照。
- `WizardPage` 在生成后和「同步翻译」时调用；提示条现在同时统计「待同步文字」和「待补译名称」。
- 注意：这改变了 v1.13 文档里「课程另一语言原名允许留空，不批量机翻」的约定——现在是**选中才补、标记 machine**，负责人可在资料库里改。

### 2.6 第二轮实测后的热修复：岗位要求判断不再卡死整份简历
负责人实测第二轮时，ABB 生成直接失败：「AI 选材局部修复失败……learning 只允许引用实际课程 ID；项目/工作事实应独立判断」。原因：AI 把几条岗位要求判为 `learning`（仅课程知识），却同时引用了课程和项目事实；局部修复也没修对，`planWithAi` 就抛错，整份简历没有生成。这些判断只用于「匹配说明」，不进入简历正文。
- `validateSelection` 现在先**自动纠正类别**（只会往低说，不会抬高）：`learning` 引用了项目 / 工作事实 → `transferable`，证据只留实践事实；`direct/transferable` 只有课程 → `learning`；`gap` 却有证据 → `transferable` 或 `learning`；非 `gap` 但没有证据 → `gap`；`learning` 缺说明 → 填默认说明。**编造 / 不存在的 ID 仍报错**并走原局部修复。
- `planWithAi`：局部修复后若剩下的问题**只在 `/requirements/N` 且不是 invalid_id**（非联合模式），就去掉这几条匹配说明继续生成，并写进 tradeoffs。
- 按新行为更新的测试：`jointV113`（课程冒充实操 → 降级而非报错；格式错误用例不再要求 requirements/4 报错）、`coursesV113`、`aiPlannerV112`（修复后空证据 direct → gap）。新增 `writingV2026_11` G 组复现 ABB 失败。

## 4. 已知问题 / 风险

1. **译文缺失时英文版会显示中文**：`layout.ts` 的 `B()` 在某条没有目标语言时显示另一语言（设计如此：新勾选的素材先显示原文，等用户点「同步翻译」）。如果本地化失败，导出的英文 PDF 仍可能夹中文。可考虑：导出前若英文版存在中文，提示一键补译。
2. 新的放宽护栏可能偶尔放过措辞层面的轻微夸张（例如把「参与」写成「负责」会被拦，但写成「完成了 X 的设计」在原文没有未完成字样时不拦）。这是负责人接受的取舍。
3. `entityTokens` 对英文会把带两个大写字母或数字的词当工具名，AI 若用了原文没有的缩写（如 LAN）该条英文会回退到重新本地化。
4. 旧浏览器里已导入的资料仍是旧结构（技能分组 = 【】标签、名称带句号）。负责人会**重新导入** V7，不需要迁移；若以后要兼容旧数据，需要写一次性清理。
5. 工作经历的单位全称与起止年月以负责人 2026-11-02 版 V7 为准（旧交接里另一种单位写法和「2023–2025」的说法已作废）。仓库公开，不要把真实单位名、联系方式写进文档或测试。
6. 云端环境（Claude Code 远程会话）装依赖要走代理：`NO_PROXY=localhost,127.0.0.1 no_proxy=localhost,127.0.0.1 npm_config_noproxy=localhost npm ci --cafile=/root/.ccr/ca-bundle.crt`；pip 同理加 `--cert`。浏览器 e2e 需要 `CHROMIUM_PATH=/opt/pw-browsers/...` 和 `pip install PyMuPDF`。

7. **超页风险**：第二轮鼓励填满后，若 AI 主选就超过一页，`fitContent` 只能撤回候补并提示「主要内容超过目标页数」，不会自动删减主选。若实测经常超页，考虑：按优先级自动去掉末尾的次要要点 / 课程，或把课程行截短。

### 2.21 「自动调整为 1 页」（2026-11-05，负责人需求）
- 第 3 步「篇幅」那一行新增按钮「自动调整为 1 页」（`data-testid=fit-one-page`）。只微调版式参数、**不删内容**：把正文字号、行距、板块间距、条目间距、页边距**同比例**从当前值往下限推，用真实 PDF 页数（`measurePages`，按 `autoFit:false`）二分查找「刚好放进 1 页」的最小幅度（`src/export/autoOnePage.ts`，`fitToOnePage`）。中文版、英文版各自调（写到 `locales[lang]` 的覆盖，两种语言相同时收回模板本体）。
- **下限**（`FIT_LIMITS`，负责人让自己定）：正文 ≥ 9.5 pt、行距 ≥ 1.12、板块间距 ≥ 1 mm、条目间距 ≥ 0.3 mm、页边距 ≥ 10 mm。当前值本来就低于下限的项（如手动 6 mm 页边距）保持原样，绝不调高。
- **放不进的处理**：推到下限仍超 1 页 → 不做任何修改（压到下限仍是 2 页只会更难看），提示可改用「自动删减到 1 页内」（§2.20）或改 2 页。负责人原话是「实在不行就维持 2 页，能调多少是多少」，这里理解为「保持原样」；如他希望「放不进也推到下限」，改 `fitToOnePage` 的 failed 分支即可。
- 结果提示（`data-testid=fit-result`）逐语言写明调了什么，带「恢复调整前的版式」按钮（`fit-undo`）。
