## 真实格式暴露的根因

1. V7 使用 `01｜栏目`、`[x] 编号｜内容` 和无表头的固定课程列；首轮解析器仅支持另一种字段标签/表头格式。真实文件首次检查正确识别的本科课程为 0；硕士授课也没有正确映射，并误把一条成绩汇总当课程。完整性检查阻止了写入，未修改任何真实资料。
2. **事实编号不等于实体编号**。EDU-M/B 的学校、学位、专业、时间各有编号；PRO 的 41 条事实属于两个项目。逐编号创建实体会形成碎片、错误学历与重复项目。
3. MSC-S01/S02 是成绩页面/汇总元信息，不是授课课程；ENG5813/ENG5814 是核心项目相关信息，不能凭出现课程代码增建学历或课程。
4. 课程实践要在课程命名空间内按 Q、Lab、Assignment、Workshop 分组，不能按共同软件或相似名称合并。组织经历也要区分部门、职责补充、兼职与志愿；测试修复了“参与”开头的志愿经历被误接到上一条兼职的问题。
5. 课程成绩不仅出现在 grade 字段，也出现在教育成绩页摘要中；新增私有来源账本和原件备注需要一起从生成副本/投递快照移除，避免旁路暴露默认隐藏成绩。

## 最终实现

- 为事实级编号格式增加确定性解析路径，兼容首轮的字段式编号导入及原来的非编号 AI 导入。
- 新增可选 `profile.sourceFacts` 私有账本，逐条保存原编号、栏目、完整事实块、审核标记和实体映射。预览与保存后可展开“逐条事实来源”；内部 ID 重分配不会改写来源编号，关联在写入后统一映射。
- 教育按命名空间归为本科/硕士各一条；核心项目按项目命名空间归为两项；工作、论文、个人工具的属性组装到各自实体。实践按明确任务标签分组，不拆成无意义的微型项目。
- 本科列分别读取中文名、英文名、学分、原成绩和概述；硕士列分别读取学期、原代码、双语名、原成绩及续行说明。原件没有逐门硕士学分，字段留空；不推算、不补数。成绩汇总保存在教育备注，不能冒充课程。
- `[x]` 确认事实记录；不把它升级为官方教学大纲或职业实操。两条遮挡成绩保持 unverified，三条未公布成绩保持 not-released；课程记录可导入，成绩默认隐藏，不制造“必须补交证明”任务。
- 稳定来源身份负责去重；明确的同一实体事实组先组装再预览。不同课程任务、不同部门和工具不会因关键词相同而合并。工具关联来自原文精确名称和明确使用上下文，限定名会遮蔽短名，例如 Python Commands 不会成为独立 Python 实操证据。
- 真正的重复编号矛盾、同实体学校等关键字段矛盾、课程遗漏和未知类型仍会报错/阻止写入。覆盖已确认记录仍需二次确认；接受纠正原文时同步更新对应来源账本。
- 私有备份保留账本和原文；生成副本/投递快照移除来源账本、原文、导入历史和原件备注中的成绩页摘要，正文事实与临床/仿真边界仍保留。清空功能覆盖账本，API/投递保留不变。

## “15 项重复、80 项待核对”的实测与边界

附件包含事实母库，**不包含当时 DeepSeek 返回的 JSON 或那 15/80 项预览清单**，因此不能逐项还原历史列表或声称每一项已有一一对应。

当前真实文件的确定性路径实测：

| 指标 | 首次导入隔离空库 | 同文件重导入 |
| --- | ---: | ---: |
| 新增实体 | 166 | 0 |
| 明确已有实体 | 0 | 166 |
| 内部重复/可能重复/冲突/待决定 | 0 | 0 |
| 缺失信息/强制待核对提示 | 0 | 0 |
| 强制上传证据任务 | 0 | 0 |

A：已确认事实直接导入；B：明确未知、遮挡、未公布保存原状态，不产生强制补充任务；C：真正矛盾仍保留拦截与覆盖确认。此处的 0 不表示删除未知原文或关闭安全检查，注入遗漏、重复编号/身份矛盾与覆盖已确认值的回归仍验证拦截。与已有、缺少来源 ID 的旧 AI 资料合并时，无法确认实体身份的记录仍可能要求人工判断，不会自动删除用户旧记录。
