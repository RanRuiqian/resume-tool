## 实现与使用路径

1. 向导第二步保留「单岗位模式」，增加「同一企业多岗位联合匹配」。每组填企业与 1–3 个岗位，各自有名称、正文、链接、独立截图/OCR 和多文件/拖拽/粘贴入口。每个岗位单独解析，可检查硬性/可选要求、职责和工具，再统一准备生成。新建组保留旧组；移除岗位是归档，可恢复。
2. 每份 JD 有稳定角色 ID、独立分析 ID、追加的 revision 和原文/截图快照。文字不变时复用解析，显式强制重解析才新建版本。共同企业名称与解析企业不一致时要求用户核对，不能默认为同一家。重新解析或改变联合组不覆盖旧简历及人工选择，必须明确点击重新生成。
3. 逐岗解析之后，用现有一次 AI 选材读取完整课程、项目和实际经历，同时归纳共同/互补/冲突要求；再撰写、双语本地化，只有一份共同内容，不为每个岗位各调一次 Pro 生成不同简历。没有额外单独的“联合归纳”模型轮次。同一 JD 未改时不重复付费解析。
4. 每岗每条要求有精确 requirementId，AI 必须逐条完整返回原要求、层级、来源 ID、匹配判断及原因；不允许丢掉弱项、降低层级或挪用别岗要求。共同/互补归纳合计完整覆盖所有要求，冲突跨岗引用真实要求。ID/证据边界错误使用既有一次局部修复，保留合法部分；修复仍失败就停止，不规则降级。
5. 课程语义选材读取正式名、别名、一句内容概述、知识标签、概述证据等级和关联真实项目。按“岗位能力→课程内容→项目/工作验证”判断，不要求标题关键词完全相同。AI 可选只打印名称的课程；概述、推断、成绩不进入写作 facts。课程 ID 只能作 learning 知识支持，不允许 direct/transferable 实操判断；课程不能支持熟练 PLC、供应商开发或合同谈判等没有职业事实的结论。待审核、停用、项目学分和无教育关联课程不自动入选。
6. 生成后显示各岗位的实际事实/可迁移背景、课程知识支持、无证据缺口及过度宣传风险。来源 ID、类别、原文摘录、概述等级、AI 关联理由都可追溯；课程/可迁移不等于岗位实际工作。手动勾选、取消与排序会保留，报告明确标注“本简历已采用/未采用该来源”，不拿母库中未采用内容冒充正文亮点。原有逐句事实审查保留，报告不授予自动放行。
7. 岗位差异、冲突、缺少共同要求或明显缺乏证据时警告“单份简历难以同时强匹配”，允许继续，也可切回单岗。联合模式不展示一个平均匹配分作为保证。报告可查看/下载，并附入 ZIP 的 `evidence-and-gaps.json`。
8. 显式点击「将同一版本关联到 N 条投递记录」，在一个事务内冻结 profile/template/resume/job 的共同快照，并建立 1–3 条申请关联。同一个 SHA-256 内容版本 ID，所有引用导出同一内容与冻结模板。重复点击幂等；改简历后明确再次关联才产生新版本，旧版本和已提交记录仍保留。新记录仅“待投递”，不猜投递时间，不访问招聘官网。既有状态/投递时间不改为待投递。

## 数据与事实安全

- Dexie v6 仅新增 jdGroups 与 resumeVersions；v5 所有旧行与设置/Key/历史/附件原样保留，P0/P1 的升级前备份保护继续生效。
- 归档 v2 加入上述两表，仍读旧 v1。版本恢复检查哈希；同 ID 不可变内容冲突则整个恢复事务失败，不能覆盖。有关联指针的记录不能在缺少共同版本时静默恢复成悬空引用。
- 共同版本保存当时的模板，后改字号/顺序/模板不改变历史内容。哈希证明字节内容完整性，不证明事实真实；事实仍需要用户审查。PDF/Word 元数据生成时间可以不同，但不会为三岗生成不同正文冒充同版。
- 母库原文、成绩、简介不改写。结构化课程成绩在 AI payload、新隐藏成绩缓存/快照、HTML/PDF/DOCX 中默认隐藏，只有用户逐课明确开启的原始成绩能保存到该简历快照；不换算 GPA。私有母库备份继续完整存档成绩。
- 保留 Marine Engineering 等正式专业名、原始语言证据、实习/工作/校园性质、固定双语简介；不会因为共同 JD 改写成另一学位或凭空添加语言熟练程度。GitHub/网站/作品集的独立开关沿用 P0/P1。
- AI 写作只接收选中的工作/项目事实与有证据的岗位方向；缺口单列且禁止写成个人事实，课程概述不作为职业写作素材。既有 guardRewrite、实体、数值、限定、双语一致性、sourceIds 归属和高风险事实确认继续执行。
- 所有开发与自动化为虚构人物/企业/课程/成绩、临时浏览器库和模拟 API。没有读取真实用户母库或调用真实 API Key。

## 人工验收（7 步）

1. 私有备份真实母库，核对旧简历/设置/求职记录仍在。首次优先用独立浏览器资料测试；不要将虚构 fixture 导入正式资料库。
2. 在第二步显式切换联合模式，填同一企业的三岗名称和 JD，分别上传/粘贴正文或截图，检查每岗独立解析，确认企业名称与原要求。
3. 点击准备联合生成，然后明确生成共同简历；查看共同/互补/冲突归纳和各岗所有要求是否完整，缺口是否诚实。
4. 核对课程关联依据与等级。确认只提供知识支持，未将 Supply Chain 推成供应商开发，未将辅机推断变成熟练 PLC；用真实项目事实确认实际实践。
5. 手动增减/排序素材与课程，核对简介、正式专业、语言证据、工作/校园分类、链接与成绩开关，再逐句完成事实审查。
6. 关联三条投递记录，核对相同共同版本 ID、待投递状态和没有伪造申请时间；修改/重解析一个 JD 后确认旧简历和历史版本不被覆盖，明确生成/关联才新增版本。
7. 下载中英 PDF/Word 与逐岗报告，检查一/两页、文字/字体/分数；在 Word 中检查真实视觉分页，确认本公司应使用共同版或改回单岗版本后才人工投递。
