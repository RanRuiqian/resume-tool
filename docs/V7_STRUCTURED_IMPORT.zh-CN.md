## 根因：已确认的代码路径与尚待复现的现象

1. 原智能导入 schema 把课程放在 `education.courses: string[]`，没有直接写独立 `profile.courses`；用户需要另行导入课程，前端缺乏一份统一的课程完整性清单。
2. 原分段按约 6000 字符切割，长段落可能从记录中间切开；每段模型输出最多 8000 tokens。未发现一个把全文统一截成固定总长度的逻辑，但这些限制与自由 JSON 输出无法证明每条记录都在。原来没有来源编号清单来检测模型静默漏项。
3. 原 AI schema 不携带来源实体 ID，分段映射生成临时 ID；去重预览还会取名称相似度的较高值，可能把共同软件、相似实验名推成重复候选。
4. 原 UI 为无开始日期的教育/工作/项目统一加提示，AI 自报的不确定内容也直接汇总；无法区分已审核事实、明确未知、真实矛盾。
5. 既有应用计划通过全局 JSON 替换重分配所有 `id`。新增来源元数据后，这会改坏来源编号；现已改为只重分配内部实体/要点 ID。

没有 V7 原件及当时 15/80 项具体清单，不能断言每个现象的唯一原因，也不能编造逐项修复结果。

## 修改内容

- 编号 TXT 优先本地确定性解析，无自由生成、无条数/输出 token 限制，不自动翻译或重写已审核原文。非编号普通资料继续使用原 AI 导入功能。
- 按 01–14 栏目和稳定编号逐条建立清单；保留来源 ID、完整原文块、课程名称、原代码、学分、原始成绩和说明。支持字段标签与带表头的课程表；不支持的布局明确报遗漏，不能显示完整或确认写入。
- 本科/硕士课程进入独立课程库；项目学分只关联已有项目，不扩增教育经历或核心项目。核心项目、辅助实践、工作/组织、技能保持分类。
- 同编号按来源身份匹配；相同母库重复导入不增加实体和原文副本。不同编号的实验、作业、部门、工具保持独立。与无编号旧数据比对时，仅可验证的实体属性支持自动合并；不确定的旧记录仍保守要求判断。
- 所有新实体写入后统一重映射课程→教育、实践↔课程、技能→经历。悬空引用显式显示，不用过滤掩盖丢失。
- `[x]` 确认记录事实；未知日期不推测，遮挡/未公布成绩原样保存。它不等于官方大纲、软件熟练或实操证据，原有生成事实检查和成绩隐藏保留。
- 不从“报告/截图/论文”等名词创建强制上传证据任务；附件管理功能保留。
- 预览显示原文/已识别/遗漏，列出遗漏编号和原因。重复编号、同字段矛盾、与已确认旧资料冲突仍须处理；完整性未通过在 UI 与写入函数两处阻止写入。
- 私有备份保留来源；生成副本与不可变投递快照不带原文元数据/导入历史快照，避免通过旁路暴露课程成绩。
- 保留一键清空、API 配置、课程管理、联合岗位、模板与原有导出。

## 原先 15 项重复与 80 项提示

原先具体清单尚未取得，暂不能提供逐项前后数量。程序采用以下可测试规则：

| 情况 | 处理 |
| --- | --- |
| 同来源 ID、同事实 | 自动匹配合并，不新增记录 |
| 同教育实体的可靠补充片段 | 学校、学位、专业、开始日期一致且结束不矛盾时合并 |
| 不同编号的 Lab 2A/2B、Assignment 1/2、不同部门、Python/VC Commands、GitHub/Pages | 保持独立，不按共同关键词或名称包含关系合并 |
| 与旧无编号资料无法确认是否同一实体 | 保留人工决定，不擅自删除旧资料 |
| A：已审核明确事实 | 导入，不制造缺日期/缺证明提示 |
| B：原文明示未知、未公布、遮挡 | 原样保留状态，不编造，不要求补充才能导入 |
| C：同编号不同事实、同字段矛盾、与已确认记录冲突 | 显示对应 ID 与冲突，保留旧值，须人工选择 |
| 实际解析遗漏或未知映射 | 明确显示缺项与原因，阻止虚假完整写入 |

虚构干净样本没有“缺失信息/待核对”或“需决定”提示；注入的真实冲突和遗漏会被拦截。这不等于把真实 80 项直接删除或全部消除。
