# v1.12 AI 主导选材与简历规划（开发分支说明）

日期：2026-11-01；目标分支：`feat/ai-led-resume-planning`。未合并、未部署，正式站仍为 v1.11.0。

## 为什么要改

v1.11.0 在真实 ABB 机械设计岗位验收中遗漏了重要的本科毕设、保留无内容工作条目和无关细节。根因之一是固定关键词算法先剔除经历，再把有限事实给 DeepSeek，只允许 AI 润色，令模型无法自主选择更适合的项目。

## 新流程

1. OCR 仍沿用已有视觉模型；**JD 结构化解析升级为 Pro + thinking**，由 AI 深度区分真实职责、硬性条件和加分项。未修改 JD 时沿用之前的分析结果，重新分析按钮可触发新解析。
2. **Pro 选材**：`selectionBrief` 读取所有启用且有有效要点的工作/项目、教育、技能、证书、奖项，连同 JD 发送到 AI；AI 评估必备/职责/加分项与直接/迁移/缺口证据，按其专业判断选择项目顺序、要点、技能及证书，返回精确 ID。
3. **本地事实边界**：`validateAiSelection` 拒绝引用不存在、未启用或其他经历的 sourceId、空白工作条目、重复事实、超页数、非官方估算 GPA、与证据不一致的岗位判断。任何选材错误最多交 AI 修正一次，不会静默套用关键词规则。
4. **Pro 撰写**：按 AI 所选的要点、岗位需求和个人简介方向写简洁的主语言版本；对存在风险的返回条目，最多再用 Pro 尝试一次安全改写。`guardRewrite` / `guardSummary` / 实体检查仍决定能否采用；失败则退回资料库原文的保守精简文本。
5. **配套求职材料**：求职信/自我介绍的重点经历跟随 AI 已经挑选的简历事实，不再单独使用关键词规则重排；求职信、面试备考方向也调用 Pro 深度判断，原有逐句事实核验及 JD 原句来源要求不放松。
6. **本地化**：副语言沿用现有翻译模型与两语言事实检查。四套模板、中英文 Word/PDF、资料母库和 IndexedDB 结构不变。

## 模型策略

- 启用 **DeepSeek 官方 API** 时，JD 解析、选材、主版本撰写、事实风险修复、求职信/自我介绍、备考方向都采用 `deepseek-v4-pro` + `thinking: enabled`。用户设定的 Flash 仍可以用于翻译等较简单任务。此策略可能提高单次成本和等待时间。
- 其他 OpenAI 兼容服务尊重用户当前选择的 `settings.model`；不把 DeepSeek 特有参数发送给其他服务商。
- `provider.ts` 新增按请求指定 `thinking` 的可选参数，普通调用保持旧有关闭思考模式行为。
- 未配置 API / API 报错 / AI 选材失败时在**真实模式明确报错**；演示模式仍使用可预期的本地规则。不会以一份错误选材的简历冒充 AI 成功。

## 隐私与数据边界

- AI 获取候选人必要的经历事实，不获取照片、姓名、电话、邮箱、出生信息、本地证据文件路径、项目档案、原始文件全文、API Key。
- 不新建、不删除、不清空数据库，不重新初始化资料库；用户依旧拥有生成结果最后审核权。
- 不写死用户个人履历、企业或项目名称。所有自动化测试使用虚构资料。

## 测试与验收

- `tests/aiPlannerV112.test.ts`：完整候选资料可见、核心毕设不被规则提前剔除、空白工作过滤、错误 ID 与估算 GPA 拦截、模型选择与思考模式、AI 失败明确报错、求职信跟随 AI 选材及备考使用 Pro、编程语言/口语证书分组。
- 旧的 `qualityV110`、`kitVerifyV1101`、`aiPayloadA4` 测试随两阶段调用适配；其他测试保持兼容。
- 下一步需要用户用**真实个人母库 + ABB JD**在浏览器人工验收：看是否保留液压毕设、耳镜项目是否合理缩短、简介是否存在、中英文 PDF/Word 是否排版正常、是否无空工作经历及虚构软件技能。
- 单元测试/mock 不能证明真实 Pro 的语义能力；未配置真实 Key 时不得声称真实 API 验收通过。

## 已知限制 / 后续阶段

- 生成正文仍使用每个 `sourceId` 一条的事实追溯约束，**尚不支持把两个不同 sourceId 的独立事实合成一个要点**，以免破坏现有人工事实审查与恢复原文功能。AI 已能决定选哪些要点、如何改写每条及项目篇幅。若真实验收确有需要，可另做多来源要点与审查升级。
- `matchScore` 是从 AI 引用真实事实 ID 的要求判断加权得到的自用参考值，不是招聘系统 ATS 或企业评分；模型仍可能有主观误判，需看对应证据。
- v1.11 已记录的求职信逐句误报及其他次要问题还需要单独修复；不能借模型升级放松事实核验。
